One event · four transformations

Identity emerges from stable evidence.

The notification is only the final output. The useful system is the grouping layer that turns noisy events into a manageable issue inventory.

01

Capture

The SDK diagnostics event arrives as nested data inside a normal service log. Datadog can store it, but Error Tracking cannot group it yet.

RAW DIAGNOSTIC EVENTstatus: info
{ "service": "sdk-diagnostics",
  "event_name": "sdk.error.uncaught",
  "event_properties": {
    "error_name": "TypeError",
    "message": "undefined is not an object… user=1842",
    "stack_unminified[0]": "snippet-index.ts:52:38"
  }
}
02

Normalize

A reversible Datadog pipeline maps the nested payload into standard error fields. Volatile IDs, URLs, and timestamps are removed from the message.

STANDARD ERROR FIELDSpipeline: active
event_properties.error_name→error.kind
normalized message→error.message
stack trace→error.stack
SDK error marker→status: error
03

Fingerprint

Error kind, normalized message, and the first meaningful SDK-owned source frame create a stable identity for the underlying problem.

04

Group, then notify
